# Codebase Audit & Plan

**Audit Date:** 2026-04-25
**Builds on:** `.planning/codebase/CONCERNS.md` (2026-03-14)

## Purpose

Confirm the codebase is on solid ground before the next feature wave (weather integration, mental-health / panic-attack tracking) lands.

## Scope

- Single-user, owner-operated app.
- Multi-tenant, scaling, rate-limiting, CSRF, and "split for scale" recommendations are **deliberately out of scope**.
- Findings filtered to: foundations, simplicity & dead code, standards, tests, docs vs reality.

## What's already solid (no action needed)

- **Secrets hygiene** — `.credentials`, `.env`, `.env.local` gitignored and never tracked. `.env.example` and `.env.local.example` correctly tracked.
- **RLS coverage** — all 3 migrations enable RLS with `auth.uid() = user_id` patterns. No anonymous-access mistakes.
  - `supabase/migrations/20260131050834_initial_health_tracker_schema.sql`
  - `supabase/migrations/20260212000000_add_user_scoped_admin.sql`
  - `supabase/migrations/20260315205207_create_event_notes_table.sql`
- **Env handling** — `PUBLIC_*` vs server vars used correctly (`src/lib/supabase.ts:3,37-39`); no sensitive secrets accidentally `PUBLIC_*`/`VITE_*`.
- **TS strict mode** on (`tsconfig.json:11`).
- **Test runner healthy** — 45/45 passing, no skips, no flakes (~815ms via `npm run test:run`).
- **Auth store basics** correct — browser-only init, `onAuthStateChange` subscribed (`src/lib/stores/auth.ts`).
- **Security headers present** — `_headers` ships HSTS (1y + includeSubDomains), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and a CSP scoped to Supabase.
- **File sizes** — `eventService.ts` (595), `exportUtils.ts` (847), `offlineQueue.ts` (342). Larger than ideal but cohesive; **don't pre-emptively split for solo use**.

## Findings

### Critical (do before next feature)

#### 1. No server-side auth enforcement

- No `src/hooks.server.ts`, no `+layout.server.ts`, no `+page.server.ts` exist anywhere in the project.
- `/admin` is gated only by `{#if $user}` in `src/routes/admin/+layout.svelte:19`.
- Cloudflare Pages serves the admin layout HTML before client hydration evaluates the auth store; brief flash of admin UI for unauthenticated requests.
- **Fix:** add `src/hooks.server.ts` validating Supabase session and exposing user on `event.locals`; add `src/routes/admin/+layout.server.ts` with `redirect(303, '/')` if `!locals.user`.

#### 2. Cloudflare Analytics on by default

- `.env.example:42` defaults `VITE_ENABLE_ANALYTICS=true`.
- `src/lib/logging/config.ts:67` enables the transport when set.
- `src/lib/logging/transports.ts:183-214` (`CloudflareAnalyticsTransport`) sends operation names and error context to gtag.
- Mental-health tracking is on the near roadmap; even pseudonymized op/error context is more leakage than this app should default to.
- **Fix:** default `VITE_ENABLE_ANALYTICS=false`; delete the transport and its wiring.

### Should-fix (do as features grow surface area)

#### 3. `any` types leak Supabase shape errors

- `src/lib/database.types.ts` is generated but UI doesn't use it.
- Sites: `src/lib/components/RecentEvents.svelte:12`, `src/lib/components/EventDetail.svelte:17-18`, `src/lib/components/history/EventsList.svelte:2`, `src/lib/utils/exportUtils.ts`.
- **Fix:** define typed result interfaces for joined queries; replace `any[]` in cited UI files. `src/lib/test/mocks/supabase.ts` may stay `any`.

#### 4. Test gaps on highest-leverage paths

- Coverage ~30% lines / 40% functions vs. 70%/70% threshold in `vitest.config.ts`.
- Right answer is targeted tests, not chasing the global %:
  - `EventService.createQuickEvent` / `createEventWithLocations` (`src/lib/services/eventService.ts`) — zero tests; only history covered.
  - `src/lib/stores/offlineQueue.ts` — zero tests; subtlest correctness risks.
  - `src/lib/utils/exportUtils.ts` — zero tests; format regressions silently break exports.

#### 5. Offline queue durability gaps

- No `JSON.parse` validation (`src/lib/stores/offlineQueue.ts:288`).
- No `localStorage` quota check before writes (`src/lib/stores/offlineQueue.ts:54, 73, 94`).
- `Date.now()` UUID fallback collision-unsafe (`src/lib/stores/offlineQueue.ts:43`).
- This is the only place data lives outside Supabase; silent corruption = lost symptom logs.

#### 6. Export query unbounded

- `getEventExportData` (`src/lib/services/eventService.ts:479+`) has no `LIMIT`.
- Today fine; with weather + mental-health tracking, event volume grows fast.
- **Fix:** add a configurable cap (e.g. 50,000); surface truncation to user.

#### 7. Docs and config drift

- `docs/development/api-design.md` documents `/api/events/quick-log`, `/api/events/{id}/interventions`, `/api/events/{id}/resolve` — none exist under `src/routes/`.
- `docs/development/developer-guide.md:70-80` example tree references `src/routes/api/events/quick-log/` — also nonexistent.
- `.env.example:48-51` defines `VITE_HEALTH_CHECK_*`; `src/lib/logging/config.ts:127-130` reads it; no `/health` route exists.
- `VITE_USER_HASH_SECRET` is read in `src/lib/logging/config.ts:194` but undocumented in `.env.example`; hardcoded fallback `'ms-tracker-default-secret'`.

### Nice-to-have (deferred — pick up opportunistically)

- **`createEventWithLocations` non-transactional** (`src/lib/services/eventService.ts:180-212`). Two queries with delete-on-failure rollback. Solo-user practical risk near zero. Add unique constraint on `(event_id, body_location_id)` + upsert pattern when revisited.
- **Offline queue retry backoff** (`src/lib/stores/offlineQueue.ts:204-213, 234`). Fixed 100 ms inter-item delay; exponential would be safer.
- **`attributes` JSON column has no schema** (`src/lib/services/eventService.ts:121`). Fine for now; schema-per-event-type is the right move when mental-health/weather event types land.
- **Prometheus transport is dead code on Cloudflare Pages** (`src/lib/logging/transports.ts:91-177`, ~85 lines). Pages cannot receive inbound. Delete.
- **CSP allows `'unsafe-inline'`** for `script-src` and `style-src` (`_headers:5`). Hardening, not a bug. Move to nonce-based CSP eventually.
- **`X-XSS-Protection` is legacy** (`_headers:9`) and redundant with CSP. Harmless but droppable.
- **Archive or remove stale `.planning/` GSD artifacts**.

## Explicitly out of scope (solo-user)

These items appeared in the prior `CONCERNS.md` (2026-03-14) but are deliberately not filed — solo single-user usage doesn't justify them:

- Query-result caching layer (`getEventHistory`, `getRecentEvents`)
- CSRF protection (RLS is the trust boundary)
- Client-side rate limiting / debounce on event creation
- Multi-tenant or multi-user concerns
- Splitting `eventService.ts` or `exportUtils.ts` purely for size
- Field-level encryption for `attributes` (re-evaluate with mental-health data)
- Custom serializer/migration support for the offline queue (covered partially by #112)

- **Nice-to-have** items don't get issues until something else forces the question.
